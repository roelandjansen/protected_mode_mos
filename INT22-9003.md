# DOS/32A warning 9003 (INT 22h) after a nested EXEC -- not a kernel bug (2026-10-08)

Result: **no change needed.** The warning also appears on a plain DOS
without PC-MOS.

## Test

DOSBox Staging's own DOS (no PC-MOS, no `$386.SYS`; DOS/32A in its own
raw/VCPI mode), `DOS32A WAXTEST WAHELLO > OUT.TXT`:

```
XTEST: parent starting WAHELLO
...
XTEST: back from WAHELLO, rc 0; parent done
DOS/32A warning (9003): real mode interrupt vector has been modified: INT 22h
```

`DOS32A WAHELLO` (no nested EXEC): no warning. This is the same pattern
as under PC-MOS.

## Why

All DOS versions do it the same way, and the PC-MOS kernel matches them:

1. EXEC sets IVT 22h to the caller's return address (`MOSFUN00`
   `fun4bw1`: `2522h`; DOSBox `dos_execute.cpp`; MS-DOS `exec_set_return`).
2. EXEC copies IVT 22h-24h into the child's PSP at 0Ah.
3. When the child terminates, IVT 22h-24h are restored from the
   **child's** PSP (`fun00b`; DOSBox `RestoreVectors`).

After the child returns, IVT 22h therefore holds the parent's EXEC return
address, not the value it had when the parent started. DOS/32A compares
the whole IVT at exit with its snapshot from startup, so it reports
22h. The parent's own termination then restores 22h from its own PSP,
so nothing is left behind.
