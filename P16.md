# P16 -- a broader 16-bit DPMI client (2026-10-08)

`P16.ASM` (MASM 5.1, `.286p`; `combuild.sh P16` -> `P16.COM`, 1,368
bytes). It enters as a 16-bit client (ax=0) and checks, by effect, the
int 31h services that 16-bit protected-mode programs rely on. `HI16`
(UPDATE 82) covers int 21h with junk in the high words; P16 covers the
rest:

| # | service | check |
| --- | --- | --- |
| 1 | 0000h/0007h/0008h/0006h | base 12345h read back, `lsl` = 0FFFh |
| 2 | 0001h | free; a second free is refused |
| 3 | 000Ah | write through the CS alias, read through CS |
| 4 | 0002h | B800h selector reads and writes the screen |
| 5 | 0100h/0101h | write through the DOS-memory selector, same bytes through 0002h of its segment |
| 6 | 0501h/0502h | 64 KB block: first and last byte through a descriptor |
| 7 | 0300h | real-mode int 21h AH=30h equals the protected-mode result |
| 8 | 0204h/0205h | own int 60h handler, then restore |
| 9 | 0202h/0203h | #DE handler with a **16-bit frame** skips the `div` (IP at frame+6) |
| 10 | 0400h | version, 32-bit host flag |

## Result (rig, UPDATE 84 kernel + UPDATE 82 `$386.SYS`)

All 10 OK, `P16: 0 bad`.

It is still a self-written client. A real 16-bit program (Borland
RTM/DPMI16BI, or a 16-bit Windows-style DPMI app) on your rig remains
the final check.
